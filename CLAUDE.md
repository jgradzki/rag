# CLAUDE.md

## Project

A learning / portfolio **RAG (Retrieval-Augmented Generation)** app: upload your own documents (PDF, TXT, MD) and chat with them. Answers are generated by an LLM from retrieved document fragments and cite their sources.

- **backend/** - Python 3.13, FastAPI, LangChain (`langchain-core`, no `langchain-community` - it is being sunset)
  - `app/main.py` - `create_app()`: builds the `RagService`, indexes the samples, adds CORS and the routers (uvicorn runs it with `--factory`)
  - `app/config.py` - settings from `.env` (pydantic-settings)
  - `app/api/` - the HTTP layer: one `APIRouter` per resource in `routes/` (`health`, `documents`, `chat` - an SSE stream emitting `sources`, `token`, `error`, `done`); `deps.py` gives routes the settings and the service (`Depends`, from `app.state`); `guards.py` is an ASGI middleware that checks the Origin and the body size before FastAPI reads the body (a dependency would run only after the upload is on disk); `schemas.py` request/response models; `sse.py` formats the SSE events
  - `app/rag/` - the pipeline, no FastAPI imports:
    - `service.py` - `RagService`: Chroma vector store, retrieval, streaming answer
    - `ingest.py` - file loading (pypdf / plain text) and chunking (`RecursiveCharacterTextSplitter`)
    - `embeddings.py` - local multilingual embeddings via `fastembed` (independent of the LLM provider)
    - `llm.py` - LLM factory: Claude (`langchain-anthropic`) or local Ollama (`langchain-ollama`), chosen by `LLM_PROVIDER`
    - `prompts.py` - system prompt and context formatting; `citations.py` - the streamed [n] citation filter; `models.py` - dataclasses shared with the API
  - `sample_docs/` - indexed automatically on the first start
  - `tests/` - pytest, `api/` and `rag/` mirror the app; fake LLM and fake embeddings (no network, no API key)
- **frontend/** - React + TypeScript (Vite); dev server proxies `/api` to the backend
- **.claude/** - project skills and their agents:
  - `cr` - multi-agent code review (`/cr`, `/cr fix`), read-only `cr-reviewer` agents
  - `test` - static checks + agentic live tests on isolated app instances (`/test`, `/test static`, `/test live`), `live-tester` agents; `ask.py` is its chat helper

## Commands

The `Makefile` is the entry point (run from the repo root; `make` lists the targets):

```bash
make setup      # venv (Python 3.13; newer versions may lack numpy/onnxruntime wheels) + requirements-dev.txt, npm ci, backend/.env, pre-commit hooks
make lock       # after editing backend/requirements*.in: re-pin all Python dependencies (uv, universal lock)
make lock-upgrade  # move the pins to new releases (P=<package> for one); make lock keeps them
make dev        # backend :8000 + frontend :5173, auto-reload
make test       # pytest
make lint       # ruff check + oxlint
make format     # ruff format + prettier
make check      # CI's checks: lock files up to date (make lock-check), lint, format check, tests, frontend build (CI also builds the Docker images)
make up / down / logs   # Docker app on :8080 (docker-compose.yml)
make shots      # README screenshots (frontend/scripts/screenshots.mjs, Playwright): own backend with only the sample docs, LLM from backend/.env; overwrites docs/screenshots
```

- On Windows the Makefile runs recipes with Git's `sh` (`C:/PROGRA~1/Git/usr/bin`), so it works from PowerShell too; recipes must stay POSIX sh.
- Python dependencies are listed in `requirements.in` (runtime only - it goes into the Docker image) and `requirements-dev.in` (test/lint tools). `make lock` compiles them into `requirements.txt` / `requirements-dev.txt`, which pin every transitive package too, with markers for platform-only ones (`uv pip compile --universal`, so the lock is valid on Windows and in the Linux image) - never edit the `.txt` files by hand.
- In Docker, nginx serves the frontend and proxies `/api` with `proxy_buffering off` - required for streamed answers. The backend reaches host Ollama via `host.docker.internal`.

CI (`.github/workflows/ci.yml`) runs the same lock/lint/format checks, tests, the frontend build and the Docker image builds on every push.

## Rules

1. **English only in project files.** All code, comments, docstrings, identifiers, commit messages, documentation (README, this file) and sample documents are written in English. Conversation with the user may be in Polish, but nothing Polish goes into the repository - except test data that checks non-English input (the Polish regression questions in the `test` skill).
2. **Fold fixes into the commit that introduced the code, unless it is pushed.** A fix of code from an unpushed commit goes into that commit (`git commit --fixup=<sha>`, then `git -c sequence.editor=: rebase -i --autosquash <sha>^`) instead of a separate `fix:` commit. Only when the fixed code is already pushed (`git branch -r --contains <sha>` prints anything) does it get a new `fix:` commit - never rewrite pushed history.
